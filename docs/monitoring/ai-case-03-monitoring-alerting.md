# ai-case-03 监控与告警方案

## 1. 目标
围绕“登录首页 + 工作台闭环”定义上线后关键监控指标、阈值与响应动作。

## 2. 指标与阈值

| 指标 | 数据来源 | 告警阈值 | 级别 | 触发动作 |
| --- | --- | --- | --- | --- |
| 首页可用率 (`index.html` 200 比例) | Nginx 日志 + 合成探测 | `< 99.9%` (5 分钟) | P1 | 通知值班工程师并启动可用性排障 |
| 登录成功率 | 前端埋点 (`login_attempt`/`login_success`) | `< 98%` (10 分钟) | P1 | 通知值班 + 启动回滚评估 |
| 登录门禁有效率 | 前端埋点 (`gate_block`/`gate_bypass`) | `< 99.5%` (10 分钟) | P1 | 判定门禁失效，执行热修或回滚 |
| RAG 流式请求错误率 | 后端接口日志 | `> 3%` (5 分钟) | P1 | 电话呼叫值班，必要时回滚 |
| 首分片延迟 P95 | 前端埋点 + API 计时 | `> 2000ms` (5 分钟) | P2 | 通知 `#ops-alerts` 并排查模型链路 |
| 流式异常中断率 | 前端埋点 (`stream_abort`/`stream_done`) | `> 2%` (10 分钟) | P2 | 排查网络/通道稳定性，必要时降级 |
| 会话恢复成功率 | 前端埋点 (`session_restore_ok`/`session_restore_fail`) | `< 99%` (10 分钟) | P2 | 检查 `localStorage` 与兼容逻辑 |
| 知识库标签加载失败率 | 接口日志 `query_rag_tag_list` | `> 5%` (5 分钟) | P2 | 通知后端值班，前端进入保底标签模式 |
| 上传入口跳转失败率 | 前端路由埋点 | `> 1%` (1 小时) | P3 | 建缺陷单并纳入下一迭代修复 |

## 3. 告警响应流程
1. 告警触发后 5 分钟内完成 ACK。
2. P1 告警持续 15 分钟未恢复，自动升级为“回滚评估”。
3. 若确认影响主链路，按 `docs/release/ai-case-03-release-rollback.md` 执行回滚。
4. 告警解除后 24 小时内完成复盘和阈值校准。

## 4. 值班通知机制
- 实时通道：`#ops-alerts`。
- 升级通道：电话呼叫值班工程师。
- 业务同步：`#engineering` 发布处理进度与结论。
